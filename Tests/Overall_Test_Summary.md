## 3. บทวิเคราะห์ทางวิศวกรรมซอฟต์แวร์ (Software Engineering Insights)

1. **สถาปัตยกรรม OOP + Layered Architecture:**
   - การแยก Domain Model (`News_Evaluation.ts`) สำหรับ Validate ข้อความ ออกจาก Controller (`News_Analysis_Controller.ts`) ทำให้ระบบสามารถดักจับเคสขอบเขต (TC08, TC09) ได้ตั้งแต่ Client-side และ Next.js API Layer ช่วยลดภาระการส่ง Request ไร้ประโยชน์ไปยัง Inference GPU Server
2. **ความเสถียรและ Fault Tolerance:**
   - ระบบมีการออกแบบ Service Factory Pattern (`Inference_Service_Factory.ts`) ทำให้ในกรณีที่ GPU Serverless เกิด Cold Start หรือ Timeout ระบบจะมี Fallback ที่สามารถตอบสนองผู้ใช้ได้อย่างต่อเนื่อง ไม่เกิดหน้าจอขาว (White Screen of Death)

## 4. บทวิเคราะห์ทางภาษาและการเรียนรู้ของโมเดล (NLP & Error Analysis)

1. **พลังของ Self-Attention ในโมเดล WangchanBERTa:**
   - ในเคส **TC04** (ออกกำลังกาย 150 นาที) และ **TC15** (ลดหวาน มัน เค็ม): WangchanBERTa พิสูจน์ให้เห็นว่าเข้าใจโครงสร้างประโยคระดับลึก (Deep Semantics) และสามารถแยกแยะคำแนะนำสุขภาพแท้จริงออกจากข่าวปลอมได้ ต่างจาก Baseline (TF-IDF) ที่หลงทางเพราะเจอน้ำหนักคำเดี่ยวๆ อย่างคำว่า "หัวใจ", "เสี่ยง", "หวาน"
2. **บทบาทการเป็น Guardrail ของโมเดล Baseline:**
   - ในเคส **TC14** (มี URL หลอกลวง): โมเดล Baseline ตรวจจับคีย์เวิร์ดฟิชชิ่งได้แม่นยำกว่า Transformer เนื่องจากคำศัพท์ URL แปลกใหม่ทำให้ค่า Attention ของ Transformer กระจายตัวออก การทำงานแบบ **โมเดลคู่ (Dual-Model)** จึงช่วยปิดจุดบอดซึ่งกันและกันได้อย่างสมบูรณ์แบบ
3. **การค้นพบ Co-occurrence Bias (จุดที่ต้องพัฒนาต่อ):**
   - ในเคส **TC02** (ไข้เลือดออก/ระบาด) และ **TC19** (ตรวจมะเร็งฟรี): โมเดลมีแนวโน้มเกิด False Positive เนื่องจากคำว่า "มะเร็ง", "ฟรี", และ "ระบาด" ในคลังข้อมูล LimeSoda มักปรากฏในข่าวปลอมเป็นส่วนใหญ่ ทางแก้ในอนาคตคือการทำ Data Augmentation สำหรับข่าวจริงของหน่วยงานรัฐ
